## 같은 주문을 매장과 결제 서버까지 이어갑니다

**신규 결제 기능은 PR 검증 버전입니다. 아래 녹화는 CI의 실제 HTTP 서버 결과이며, 기존 공개 주소에 새 결제 버전을 배포했다는 뜻은 아닙니다.**

**[VIDEO_SECONDS초 실제 실행 영상](docs/media/payment/pickup-pact-payment.mp4)** · [촬영·원본 대조 기록](docs/media/payment/capture.json) · [검증 범위](docs/payment-release-verification-2026-09-30.md)

[![승인 응답 끊김, 두 가맹점 단말, 마지막 원본 대조](docs/media/payment/pickup-pact-payment.gif)](docs/media/payment/pickup-pact-payment.mp4)

첫 화면의 **이 조건으로 체험 시작**으로 웨이브 라떼 1잔에 500원 쿠폰과 1,000P를 적용합니다. **주문 → 매장 혼잡 → 새 매장 거절 → 응답 끊김 → 자동 재확인 → 제조·수령 → 결과 대조**를 한 번에 한 행동씩 안내합니다. 직접 시간·메뉴·예산을 고르는 기존 설정도 유지했습니다.

이번 확장은 결제 성공 화면만 추가한 것이 아닙니다. 주문 서버, 가맹점 HTTP 프로세스, **별도 DB를 가진 가상 결제 HTTP 프로세스**를 연결했습니다. 결제 서버가 승인·확정·해제를 저장한 뒤 응답을 끊어도 저장된 거래 키로 재확인합니다. 알림은 서명과 중복을 검사한 뒤 재조회 신호로만 사용하며, 알림만 믿고 결제를 성공으로 바꾸지 않습니다.

| 가상 카드와 장애 체험 | 두 매장의 단말 기록 | 무엇이 지켜졌나요? |
|---|---|---|
| ![가상 결제 선택과 쉬운 시작](docs/media/payment/01-home.png) | ![이전 자리 해제와 새 매장 제조](docs/media/payment/07-merchant.png) | ![주문·매장·결제·혜택 네 가지 대조](docs/media/payment/08-receipt.png) |

**승인 보류 두 건과 중복 청구는 다릅니다.** 2,800원 주문을 3,200원 매장으로 바꿀 때 고객이 차액에 동의하면, 새 3,200원 승인 확보 → 매장 변경 → 이전 2,800원 승인 해제 순서로 처리합니다. 수령 후 확정 청구는 3,200원 한 건, 남은 승인 보류는 0원인지 별도 원장을 조회해 확인합니다. 승인 한도를 넘거나 새 승인이 거절되면 기존 주문과 승인을 유지합니다. 이 보류·수령 시 확정 규칙은 자체 가상 규약이며 실제 PG사의 기능을 주장하지 않습니다.

가상 카드에는 실제 카드번호를 입력하지 않습니다. 접힌 **가상 카드·결제 상황**에서 승인 거절, 승인/확정/해제 응답 끊김, 중복/늦은 알림을 선택할 수 있습니다. 아직 확인되지 않은 승인·결제·취소는 완료로 표시하지 않습니다.

<summary>모바일 결과와 검증 범위</summary>

<img src="docs/media/payment/mobile-result.png" alt="모바일 결제와 수령 원본 대조" width="300">

기록이 없거나 서버를 읽지 못하면 0건·정상으로 대체하지 않습니다. 결과는 **일치 / 확인 중 / 불일치 / 자료 없음**으로 구분합니다. 읽는 동안 기록이 바뀌면 다시 확인하며, 이 조회는 분산 원자적 스냅샷을 보장하지 않습니다.

영상은 **CI의 실제 HTTP 서버 녹화**입니다. 공개 Render 녹화가 아니며, 원본 화면과 서버 응답을 가짜 결과로 바꾸지 않았습니다. 정상 속도의 장면을 연결하고 자막만 추가했으며, 제조는 화면의 체험 시계를 앞당겼습니다. 같은 커밋, 독립 서버 준비 상태, 원본 영수증과 금액을 촬영 스크립트가 확인합니다.

한 호스트의 분리된 프로세스와 보존된 SQLite 파일의 재시작을 다룹니다. 실제 가맹점·PG·카드사 연동, DB 파일 자체 유실, 멀티 호스트 고가용성은 이 데모의 검증 범위가 아닙니다. 공개 서버의 현재 버전과 결제 모드는 `/health`와 `/api/route/runtime`에서 별도로 확인합니다.

</details>

기존 네 방식 비교는 같은 v1 매장 복구 엔진을 사용하는 별도 실험이며, 신규 외부 가상 PG 흐름의 상대 성능이나 실제 패스오더의 내부 구현을 비교한 결과가 아닙니다.
