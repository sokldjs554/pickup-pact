# 독립 가상 결제 확장 — 구현 및 검증 범위

> 이 문서는 최초 로컬 구현 단계의 기록입니다. 최신 반복 실행·브라우저·촬영 결과는 [PR 검증 기록](payment-release-verification-2026-09-30.md)을 따릅니다.

기준 main: `c39cadda2f6a8c6916c21f4d4a62c828eaafc722`. 새 기능 브랜치의 개발 기록이다. 이전 공개 데모의 성공을 이번 결제 확장의 완료 근거로 쓰지 않는다.

## 반영한 코드

가상 결제 원장·명령 멱등성·승인/청구/해제 고유 제약, 독립 loopback HTTP 프로세스, 저장 후 실제 소켓 응답 누락, 프로세스 감독, 서명된 outbox/inbox 알림을 구현했다. 실제 카드번호·CVC·PG 키 입력은 없다.

새 주문의 v2 프로토콜은 저장한 단계와 외부 I/O를 분리했다. 새 승인을 확인한 뒤 이전 승인을 해제하고, 청구와 매장 수령을 모두 확인한 뒤에만 혜택을 확정한다. 기존 기록과 비교 실험은 v1을 유지한다. 외부 결제 서버가 끊겨도 v1 모의 성공으로 대체하지 않는다.

고객의 결제 상태, 두 매장의 단말, 원본 거래 목록, 주문·매장·결제·혜택의 네 항목 대조를 연결했다. 대조는 각 원본을 두 번 읽고 변경 순번과 내용을 대조한다. 분산 트랜잭션 스냅샷이나 이후 변경의 부재를 주장하지 않는다. 한 자료라도 읽을 수 없으면 UNAVAILABLE이며 청구 0건이나 정상으로 표시하지 않는다.

## 확인한 범위

로컬 SQLite·HTTP·별도 프로세스 테스트를 실행했다. 승인 거절·응답 유실·동시 청구·한도 부족·이전 승인 보존·새 승인 해제·늦은 응답의 ABORT 재활성화 차단·0원·같은 금액·감액·원본 읽기 실패·조작된 금액 불일치 등을 다룬다. 각 실행의 정확한 결과는 CI 아티팩트와 후속 PR 기록을 따른다.

로컬 핵심 전체 검사에서는 445개 중 444개 통과, 변경된 OpenAPI 스냅샷 1개 실패를 확인했다. 이후 스냅샷을 갱신하고 관련 5개 검사를 통과했다. 최종 전체 통과로 바꿔 부르지 않는다. 로컬 운영 화면 테스트는 Flask가 없어 수집하지 못했으며 설치도 DNS 오류로 실패했다. 로컬 Chromium 탐색은 관리 정책으로 차단됐고 정책을 우회하지 않았다.

`payment-review`는 정상 저장소 CI 환경에서 전체 Python 회귀 3회, 기존/신규 Node 검사, 실제 HTTP Chromium의 데스크톱/모바일 5개 시나리오 각각 3회, 새 녹화를 실행하도록 구성했다. 실행 전에는 성공한 검증이나 새 공개 영상으로 표시하지 않는다. `route-product`의 승인 수 단언은 v2 재승인의 2건과 v1 모의 승인의 1건을 구분하며 청구 1회·혜택 1회의 단언은 유지한다.

## 범위 밖

실카드·가맹점·외부 PG 테스트 연동, 유료 서비스, 멀티 호스트 고가용성, DB 파일 자체 유실, 배포 때 임시 저장소 초기화 복구, 수령 후 환불·부분 환불은 이번 구현 범위가 아니다. 승인 해제를 환불이라고 하지 않는다. 기존 41초 영상은 이전 기능의 기록이다.
