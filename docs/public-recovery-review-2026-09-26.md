# 공개 자동 복구 흐름 재검토

기준 앱: `414dac8cd5da48cf5a238fd991529d8bba944fe9` (PR #30).
공개 검증 실패: route-product `36131639244`, job `108060014641`.

## 실제로 확인한 실패
새 매장 거절, 응답 누락, 자동 복구, 제조·수령은 진행됐지만 마지막 6개 상황 비교를 기다리는 검사에서 5초 타임아웃이 발생했다. 뒤의 공개 고객·혜택·문구 검증은 실행되지 않았으므로 전체 공개 검증 성공으로 간주하지 않았다.

앱을 바꾸지 않고 같은 공개 경로의 요청·응답·화면 상태를 기록했다. 관찰 실행 `36156894258`의 첫 시도는 초기 health 20초 대기에서 멈췄다. 브라우저 검사를 실행하지 못한 실패 기록을 보존하고, 재시도에서 실제 HTTP를 관찰했다.

재시도의 비교 요청 응답은 데스크톱 7.807초, 모바일 7.714초로 HTTP 200이었다. 요청 직후 결과 영역은 비어 있고 전체 화면의 busy가 true였다. 비교는 6개 상황 × 3개 정책의 독립된 저장·명령 실행이므로 순수한 화면 갱신으로 볼 수 없다. 30초 관찰에서 결과가 나왔다는 사실을 원래 5초 검증의 성공으로 바꾸지는 않는다.

## 수정
- 비교 버튼만 잠그고 진행 중 안내를 즉시 표시한다. 내 주문·매장·영수증 조작은 비교 작업 때문에 막지 않는다.
- 요청 시작 시 조건을 복사하고 결과 위에 그 조건을 명시한다. 응답을 기다리는 동안 다른 주문을 골라도 예전 비교를 새 주문의 결과처럼 표시하지 않는다.
- 같은 비교를 중복 실행하지 않는다. 네트워크 실패·동시 실행 제한·35초 무응답은 별도 안내하고 다시 실행할 수 있도록 한다.
- 시간 제한은 주문을 바꾸지 않는 비교 API에만 적용한다. 실제 주문 변경을 클라이언트 타임아웃만으로 취소하거나 실패로 확정하지 않는다.
- 브라우저 검사는 요청 전송(5초), 응답(30초), 6개 결과의 DOM 표시(기존 5초)를 나누어 확인한다. 결과·금액·주문 ID 단언은 삭제하지 않는다. 공개 실행에서는 HTTP 매장 통신과 자동 복구가 실제 켜져 있는지도 확인한다.
- 실패했을 때도 네트워크 기록·화면·녹화를 닫아 보존한다. 원본 실패 영상이 정상 종료되지 않았던 점을 바로잡는다.

## 검증 해석
`verify_comparison_ui.cjs`는 지연된 응답을 사용하는 JavaScript 단위 시험이며 실제 브라우저 시험을 대신하지 않는다. 기존 Python/JS/브라우저/금융·혜택 규칙을 유지한다. 비교 정책이나 결과·성능을 개선했다는 주장은 하지 않는다.

후속 정확한 HEAD의 CI·main·공개 검증 결과는 각 실행 artifact를 기준으로 한다. 이전 앱의 녹화와 새 앱의 녹화를 섞지 않으며, 신규 영상과 지원 문서는 배포 검증 뒤 확정한다.
