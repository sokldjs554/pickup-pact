# 혜택을 유지하는 주문 이동과 동일 조건 비교

사용자 요청: 매장 이동이 유리한 조건과 불리한 조건을 수치로 확인하고, 쿠폰과 포인트를 직접 사용한다. 기존 주문, 제조, 수령, 영수증과 결합한다.

## 설계 결정
- 기존 제품에 확장하며 현재 main을 보존하는 작업 브랜치에서 개발한다.
- 새 일정에 체험 지갑 2,000P와 전 매장 정액/특정 매장 정액/정률 쿠폰을 제공한다. 실제 회원 계정의 여러 주문이 공유하는 지갑이 아니다. 메뉴 금액→쿠폰→포인트→최종 모의 결제 순서. 예산은 최종 모의 결제 상한이다.
- 쿠폰 하나만 선택. 포인트는 정수, 잔액 초과 입력 거절, 할인 후 금액까지만 실제 사용. 쿠폰 최소금액은 할인 전 메뉴금액 기준. 기간은 가상 시계로 표현한다.
- 주문 생성 때 쿠폰과 포인트를 보류하고 수령 때 사용 확정, 순수 모의 결제의 1% 포인트 적립. 제조 전 취소는 보류를 풀고, 반복 취소/수령은 혜택을 중복 복원/차감/적립하지 않는다.
- 이동 후보 견적에 원가, 쿠폰 할인, 포인트, 결제액, 상실한 쿠폰 이유를 포함. 동일 주문으로 이동 시 기존 보류를 원자적으로 교체. 새 금액은 서버 견적에 묶이며 이전 버전은 거절한다. 이미 보류한 쿠폰은 해당 주문에서 유효기간을 지나도 인정하되 취소 후 만료를 되돌리지 않는다.
- 비교는 두 층: 현재 동일 주문의 변경 전 예상/선택한 대안의 예상 차이를 화면에 표시; 별도 공개 실행기에서 같은 가상 초기상태/장애/미래오차를 사용하는 stay vs transfer 정책을 비교한다. 관찰 시점 이후 오차는 선택에 사용하지 않는다. 모든 사례를 분모에 포함하고 승/무/패, 비용, 이동 불가 이유, 시드별 결과를 공개한다.
- 비교는 실서비스 알고리즘이나 실제 성과가 아닌 합성 모델의 정책 실험. 제조 시작 뒤 이동 금지, 대체 매장 혼잡, 쿠폰 상실로 예산 초과, 조건 불일치도 포함. 새 실험을 기존 65회 정합성 비교와 혼합하지 않는다.
- 외부 결제/지도 연동 없음. 기존 /classic, /repair-lab, API 유지. MIT 및 새 오픈소스 라이선스 없음.

## 완료 조건
혜택 적용/미적용/만료/최소금액/보류/취소복원/수령 중복/이관 손실/예산초과/경합을 API와 UI로 검증한다. 현재 상태 비교와 고정시드 반복 실험을 실제 코드로 재현. 기존 시험 재실행. PR 및 배포는 새 SHA 검증 후에만 완료로 기록.
