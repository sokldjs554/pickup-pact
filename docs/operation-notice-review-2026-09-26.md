# 자동 복구 결과와 하단 안내의 일치

## 실제 공개 화면에서 발견

PR34 main `622687bcb464ce43fbd6e15c73bdcdfa201bffed`의 route-product36219709758은 모든 검사가 성공했다. 그러나 공개 artifact10898269824의 `decision-browser/mobile-04-recovered.png`를 열어보니 같은 주문 변경은 완료됐는데 이전의 ‘매장의 답을 확인하지 못했어요. 다시 확인해 주세요.’ 안내가 남아 있었다. 서버 오류나 중복 결제가 아니라, 6.5초짜리 안내가 자동 상태 갱신과 연결되지 않은 화면 상태 문제였다. 이 캡처를 지우거나 안내가 사라질 때까지 촬영만 늦추지 않았다.

## 원인과 수정

`cmd()`는 서버의 PENDING 결과를 성공으로 표시하지 않도록 예외로 전달했다. `run()`은 그 예외를 일반 오류 알림으로 보여줬다. 이후 GET 기반 갱신이 성공 카드를 그려도 알림에는 어떤 작업의 메시지인지 정보가 없었다.

이제 해당 알림에 체험 ID·작업 ID·상태 버전을 연결한다. 같은 작업이 자동 확인 중이면 다시 누르지 않아도 된다고 안내하고, 완료되면 확인된 결과로 바꾼다. 거절과 추가 확인 필요 상태는 오류/주의 안내를 유지한다. 수동 복구 환경에서는 자동 복구 중이라고 안내하지 않는다.

새로운 비교 오류 등 무관한 알림은 작업 범위를 초기화하므로 이전 복구 결과가 덮어쓰지 못한다. 다른 체험의 알림은 정리하고, 오래된 상태 버전은 최신 알림에 영향을 주지 못한다. 같은 확인 중 상태를 반복 조회했다고 알림의 표시 시간을 계속 연장하지 않는다. 주문·금액·예약 자리·서버 복구 타이밍은 바꾸지 않았다.

## 검증

`verify_operation_notice.cjs` 10개 격리 UI 시험 중 수정 전 5개가 실패했다. 자동 확인/완료/거절/추가 확인/체험 변경 오류를 재현했다. 수정 후 10개가 통과했다. 나머지 다섯 시험은 무관한 오류 보존, 오래된 응답, 반복 조회, 수동 복구, 실제 요청 오류의 기존 동작을 지킨다. 격리 시험은 실제 브라우저를 대신하지 않는다.

`verify_decision_browser.py`에 실제 PENDING 알림과 자동 완료 후의 알림 문구·오류 표시 검사를 추가했다. 기존 복구·같은 주문·한 번의 결제·금액 분담·네 방식 비교 검사는 유지했다. 이 변경의 정확한 PR와 main CI·공개 배포 결과는 해당 실행 artifact로 확인한다. 이전 main의 통과를 이후 버전의 통과로 계산하지 않는다.

이번 자료는 프로젝트 수정 검토용이며 자기소개서·지원 포트폴리오는 작성하지 않았다. 기존 영상은 이전 버전임을 명시한 상태로 두고, 이번 변경은 새 실제 브라우저 캡처로 제시한다.
