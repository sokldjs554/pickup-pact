# 데모 문구 정리

고객 화면, 매장 화면, 영수증, 쿠폰·포인트, 상황 비교, 기존 주문·운영 화면, 복구 작업대, 별도 운영 콘솔의 문구를 정리했습니다.

## 바꾼 기준

- 고객에게 무엇이 달라졌는지, 다음에 무엇을 누르면 되는지 먼저 설명합니다.
- `모의 승인`, `allocation`, `JIT 제조 Window` 같은 표현은 일상적인 문장으로 풀었습니다.
- 주문 번호·음료 조건은 유지되지만 쿠폰과 결제 금액은 달라질 수 있다는 안내를 구분했습니다.
- 실제 주문·결제가 되지 않는 체험이라는 안내는 첫 화면, 영수증, 복구 화면에 남겼습니다.
- 도착 시간과 정책 비교는 가상 환경의 예상값입니다. 실제 도착 보장이나 경쟁 서비스보다 낫다는 표현을 쓰지 않습니다.
- 운영 상세의 원본 이벤트 ID, 오류 코드, JSON은 그대로 두고 이해할 수 있는 설명을 붙였습니다.

## 변경 범위와 검증

표시 문자열과 표시용 변환 함수만 변경합니다. API 요청/응답 식별자, 금액 계산, 쿠폰·포인트 정책, 저장 스키마, 도메인 전이 코드는 바꾸지 않습니다. 기존 테스트의 숫자·상태·금융 단언은 유지하고 바뀐 화면의 문구와 선택자만 맞춥니다.

`tests/route/test_demo_copy.py`에서 새 문구의 초기 실패를 확인했습니다. `scripts/verify_copy_labels.cjs`는 설명을 바꿔도 원본 이벤트와 금액이 그대로인지 확인합니다. 기존 주문/혜택/복구 브라우저 검증에 더해 `scripts/verify_demo_copy_browser.py`가 실제 HTTP 화면의 빈 상태·쿠폰 상실·추가금·부분취소·기록 대기와 모바일 너비를 반복 확인합니다. 로컬 탐색이 차단되면 그 실패를 통과로 세지 않고 CI의 원본 결과로 별도 검증합니다.

README 영상과 캡처는 촬영 당시 앱 버전을 함께 표시합니다. 문구가 바뀐 앱과 이전 촬영본을 같은 버전이라고 주장하지 않습니다. 최신 검증 결과는 해당 commit의 workflow와 artifact를 확인하세요.
